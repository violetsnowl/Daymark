## 现存待修

- PR-013 课表识别偶发 `ProviderError: TIMEOUT`（服务端日志 1 次）→ 观察：有 `withProviderRetry` 重试一层，超时上限与模型耗时待核（非用户报障，暂不阻断）
- PR-014 服务端日志 2 条 `notification_deliveries` 外键失败（23503：`item_id` 不在 `items` 表）→ 通知投递引用了已被删除的事项，属独立缺陷，待定修法（删除事项时需同步清/跳过投递）
- PR-015 邮箱/短信验证码**输错**时提示「验证码已过期」（误导）→ 根因（线上实测）：Supabase 对「错码 / 过期码 / 从未发过码」一律返回 `otp_expired`（"Token has expired or is invalid"），**服务端不可区分** → 修复：`auth.err.otpExpired` 文案统一为「验证码不正确或已过期，请重新获取。」（en 同步；**邮箱与短信共用同一错误映射，一处修两端**）；顺带补齐 Supabase 现行速率限制错误码映射（`over_email_send_rate_limit` / `over_sms_send_rate_limit` / `over_request_rate_limit`）。**已修复，待随下个版本发布；网页版随构建即时生效**

### PR-002 · 服务器带宽瓶颈（根因未除）

- **发现**：2026-10-08 用户实测更新下载仅几百 KB/s；我方实测同线路 **39 KB/s（≈0.3 Mbps）**。
- **现状**：安卓下载源已切 GitHub CDN（v0.1.10 起）绕开；但**桌面端更新仍从服务器下载**、
  未来官网静态资源也在此服务器——根因（椰子云入门套餐带宽）未动。
- **2026-10-13 复测**：镜像对本机线路近乎不可用（30MB 文件实测 25 秒 / 0 字节）；安卓端下载继续以 GitHub 源为主，镜像仅剩应急意义、勿依赖。
- **处理方向**：升级 VPS 带宽套餐，或官网/静态整体迁 CDN（花钱项，待用户决策）。
- **状态**：⏸ 待决策（安卓侧已缓解，桌面 2.5MB 更新在最差情况下约 1 分钟，可忍）。

### PR-003 · 首启权限引导：小米机已验收通过；其他厂商系统未验（如实留痕）

- **验收**：2026-10-08 用户在小米（MIUI/HyperOS）真机**实测通过** ✅——通知授权随卡弹出、
  四行设置入口落点正确，引导闭环成立。
- **未验范围（如实记录）**：**仅小米一台机型**。华为 / OPPO / vivo / 三星等厂商的
  设置页层级与开关命名不同，按钮落点未在任何非小米设备上验证过；文案亦按 MIUI 撰写。
- **状态**：⏳ 本机型通过；他厂待首台真机出现时验证（发现落点错误即转「现存待修」常规修单）。

### PR-004 · 课程导入在供应商晚高峰可能连续超时（外部约束）

- **事实**：解析超时预算 300s、重试 2 次；实测出现过 240s×3 全失败（耗时约 12 分钟），
  根因为**供应商（DeepSeek）晚高峰服务端挂起**（DB 实证 preview 全空，与我方提取无关）。
- **影响**：晚高峰导入可能整轮失败，用户需改时段重试。
- **状态**：⏸ 已知外部约束（不修我方代码；可选缓解：失败文案提示"避开晚高峰重试"）。

### PR-005 · 导入中途切换账号（观察级，早期记档未收敛）

- **背景**：课程导入 job 进行中切换登录账号的归属/恢复边缘，早期验收列为观察级，
  此后未复现也未专项收敛。
- **状态**：⏸ 观察（复现路径：发起导入→解析中→登出/换号→看 job 与结果归属）。
